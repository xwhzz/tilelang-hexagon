01 背景

Hexagon 不是 GPU —— 大部分难点都源于这条鸿沟

HVX 向量

1024-bit(128 字节)寄存器 × 6 硬件线程。没有子寄存器操作 —— 每条指令都是整个 128B 寄存器。

HMX 矩阵

一个 fp16 矩阵引擎,32×32 Crouton tile。没有 mma 指令、没有可寻址累加器 —— 加载 tile 就是 MAC。

VTCM + DMA

8 MB 软件管理 SRAM。没有自动缓存、没有 SIMT。权重从 DDR 流式,靠 DMA + 显式搬运。

与 CUDA 的鸿沟: 没有 SIMT、没有 mma、没有 C_local 累加器片段、没有自动缓存。把一个 tilelang 算子搬上 Hexagon,比搬上 CUDA 难得多 —— 这决定了下面整个栈的形态。

07 战略 · 核心结论

别再打 prefill —— 打 backend 的弱项

之前 tilelang 打的是 prefill 的 HMX matmul,已 parity —— 但那是 backend 的强项,重写只能追平。真正的机会在 backend 没优化好的地方:decode。

收益最大

① decode 量化 GEMV

FFN 的 gate/up/down(69% 时间)是 M=1 GEMV,全走 HVX、HMX 闲置。写更好的量化 GEMV,或想办法用 HMX —— 直接攻那 2× 差距。

组合性

② 短卷积块融合

in_proj → SSM_CONV → out_proj(15%)是唯一没被 ggml 融合的子图(conv 夹在中间)。融合后中间量留 VTCM,省两次 DDR 往返/token。

已验证

③ 覆盖缺口

lm_head(+80%,已证)+ backend 不支持的 op/量化格式。tilelang 的价值 = 覆盖 backend 拒绝的形状,不是重写它已有的。

关键设计:Mode B(骑 host 资源)

tilelang 算子作为源码co-compile 进 libggml-htp-v79.so,复用 host 已获取的 VTCM 区 + HMX 锁,不自己 acquire session —— 这是能嵌进别人 skel 的前提。

安全边界:decline → fall through

run() 返回 -1 就回退 backend 原内核 —— tilelang 路径可以只覆盖部分形状,不影响模型正确性。

09 例子 · fused q4_0 matmul

一个 kernel 写完:DSL dequant + HMX gemm

@T.prim_func
def qmatmul(A, qcm, scb, C):        # A:激活 qcm:q4_0权重 scb:scale
  with T.Kernel(1, threads=1):
    A_sh = T.alloc_shared((M,K), "float16")
    B_sh = T.alloc_shared((K,N), "float16")  # 反量化后留 VTCM
    T.copy(A, A_sh)
    for j in T.serial(KH):              # DSL q4_0 dequant → 整宽 HVX
      for ni in T.vectorized(128):    # 填满 128B 寄存器
        q  = T.Cast("int16", qcm[j,n])   # 先加宽
        lo = (q & 0xF) - 8            # 低 nibble
        B_sh[2*j,n] = T.Cast("float16",lo) * scb[2*j,n]
    T.gemm(A_sh, B_sh, C_sh, clear_accum=True)  # → HMX
    T.copy(C_sh, C)

两层 DSL surface

简单: 上面这样,一个 T.gemm 搞定(dequant 是普通 DSL 算术)。
进阶: HMXIntrinEmitter 手驱 K-loop,让 dequant 藏在 MAC 下。

三条 HVX 铁律

① 最窄 dtype 填满寄存器(vectorized(128))
② bitwise 前先加宽到 int16
③ 权重预打包 column-major,dequant 存连续。
