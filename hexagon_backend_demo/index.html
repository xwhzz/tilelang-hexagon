01 · Project Definition

目标是 backend，不是模型专用 kernel 集合

把硬件差异收敛到 target、layout、instruction atom 和 runtime ownership。
PLATFORM

通用 target

支持 TileLang PrimFunc lowering、C codegen、构建、部署、执行和错误传播。

HARDWARE

分层硬件抽象

HVX vector、HMX matrix、VTCM、DMA 和 worker 各自有清晰边界。

INTEGRATION

两种执行模式

Standalone FastRPC 用于开发验证；embedded resource lease 用于现有 runtime。

验收标准

  • 可读：generated C 中能看到 VTCM 和硬件调用
  • 可跑：真实设备结果与 torch golden 一致
  • 可扩展：新 op 不需要复制完整 runtime
  • 可嵌入：不匹配时安全回落宿主 stock kernel

实施顺序

  • Primitive：先冻结 dtype、result repr 和副作用
  • Handwritten：建立硬件可达到的性能上限
  • Explicit TileLang：复现 loop、layout 和依赖
  • Generalize：最后接入流水、worker 和 autotune
Workload profiling 与 primitive 盘点并行进行：前者决定先优化什么，后者决定 TileLang 能可靠表达什么。

对 codegen 的影响

没有 warp/threadIdx 协作。Grid 要变成显式控制流；mixed dtype vectorization 必须满足最窄 dtype 填满 128B。

对 runtime 的影响

VTCM/HMX 是资源，不是普通地址空间；FastRPC session、worker 和 DMA queue 都必须有唯一 owner。

06 · Recipe Path

`T.gemm` 是稳定 primitives 之上的最终 recipe

先证明 explicit path，再上提高层接口。
with T.Kernel(grid_n, grid_m, threads=1): A_sh = T.alloc_shared((BM, K), "float16") B_sh = T.alloc_shared((K, BN), "float16") C_sh = T.alloc_shared((BM, BN), "float16") T.copy(A_tile, A_sh) T.copy(B_tile, B_sh) T.gemm(A_sh, B_sh, C_sh, clear_accum=True) T.copy(C_sh, C_tile)

`T.alloc_shared`

07 · Instruction-Level Path

HMX intrinsic 与 `T.Layout` 暴露正确的低层边界

不是再次封装完整 GEMM，而是让 TileLang 调度组合硬件 atoms。
acquiredependency token
→
load_biasscale / mode state
→
clearimplicit accumulator
→
K-loop mmamxmem pair = MAC
→
convert + storeCrouton C
→
releaseserialize one HMX

Activation layout

row-pair interleave，2 KiB 对齐，`T.Layout` 决定逻辑 `(m,k)` 到 Crouton offset。

Weight layout

32x32 tile，K-pair 与 channel 交织；typed pack atom 可直接写最终地址。

Output layout

convert-state 写 Crouton，再以 32-lane FP32 HVX 边界输出。

与 GPU intrinsic 的共同点

layout、load/mma/store atoms、显式 K loop、依赖关系都由 TileLang 看见，因此可以融合和调度。

必须保留的硬件差异

HMX accumulator 全核唯一且不可寻址；token 只表达顺序和存活期，不伪装成 register fragment。

08 · Runtime Modes

同一个 generated body，两种资源所有权

`num_workers=6`

外层 blocks 按 stride 分配；每个 worker 有独立 VTCM slice，HVX 工作可并行。

单 HMX spinlock

pack/unpack 可并行，隐式 accumulator 协议必须串行，不能伪造六个 HMX。

Ordered 2D DMA

可同时完成 stride 和 padding；queue、descriptor 和 cache policy 留在 runtime。

当前缺口：`T.Pipelined` 表达 stage 和依赖，Hexagon lowering 选择 ordered DMA 或 HVX fallback；queue/descriptor 不进入用户 DSL。

GENERATE

输出可直接链接的 C/C++

保留显式 layout 和 intrinsic；kernel 不依赖 ggml 类型，也不创建 FastRPC session。

CO-COMPILE

只改 source list

generated translation unit 使用 Hexagon clang，与现有代码共同链接进原 DSP skel。

CALL + FALLBACK

先固定一个调用条件

借用 llama.cpp 已有 VTCM/HMX 资源；未命中或返回失败时继续 stock 路径。

最小验收：模型 forward 命中 generated symbol、输出与 stock 一致；其他 shape 和算子行为完全不变。

16 · Conclusion

从案例验证转向 primitive-first 工程化

TileLang 可以成为 Qualcomm Hexagon 的真正 backend，而不只是 kernel generator。

四条技术结论

  • 类型先行：logical、compute、hardware repr、storage 分层
  • 低层 atom 诚实：用 layout 和 dependency 表达 HMX/HVX 差异
  • 基线驱动：手写 ceiling → explicit TileLang → 通用优化
  • 集成统一：standalone 与 embedded 共用 package contract

集中交付目录

  • `index.html`：离线演示站与打印版
  • `docs/`：架构、任务评估、讲稿和 runbook
  • `scripts/`：一条命令完成各演示阶段
  • `sources/`：TileLang 与 llama.cpp 关键源码快照
  • `artifacts/` / `results/`：已验证 skel、哈希和原始日志
